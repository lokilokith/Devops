## Matrix Mapping

| Requirement | Existing Implementation | Required Change | Test | Expected Evidence | Security Invariant |
|---|---|---|---|---|---|
| **1. Target Account Binding Model** | `Resource` model exists in `app/resources/models.py`. Authorization context defines `target_account_binding_id`. | Create `TargetAccountBinding` model in `app/resources/target_account.py` (or `app/target_accounts/`) with `(control_plane_user_id, resource_id)` unique constraint and `(resource_id, target_os_username)` unique constraint. | `tests/target_accounts/test_binding_model.py` | Schema migration creates `target_account_bindings` table; duplicate `(user, resource)` rejected by DB. | Invariant 1: At most one target account per (user, resource) pair. Invariant 2: Two users never share an OS account. |
| **2. Deterministic Username Derivation** | None. | Implement `derive_target_username(cp_user, resource, existing_usernames)` enforcing POSIX-safe slug, $\le 32$ length, reject metacharacters, reject protected accounts, deterministic collision numeric suffix. | `tests/target_accounts/test_username_derivation.py` | Valid slugs generated; shell metacharacters and traversal rejected; collision suffix generated deterministically. | Callers cannot supply arbitrary unvalidated or colliding target usernames. |
| **3. Binding Lifecycle State Machine** | None. | Implement states: `PENDING` $\rightarrow$ `ACTIVE` $\rightarrow$ `SUSPENDED` $\rightarrow$ `REMOVED`. | `tests/target_accounts/test_binding_lifecycle.py` | State transitions verified; database state is never marked `ACTIVE` without independent verification. | Target-Side Truth Rule: DB state is not evidence of OS account reality. |
| **4. Vault Key Generation for Human Accounts** | `app/vault/ssh_keys.py` generates in-memory Ed25519 keypairs. `VaultService` creates KMS-wrapped secrets. | Create human account credential in Vault Plane; pass only public key to Execution Plane; private key stays in Vault. | `tests/target_accounts/test_provisioning_vault.py` | Vault secret version created; public key extracted; private key zeroized from heap after use. | Invariant 9: No plaintext private key transfer to web API, logs, or audit records. |
| **5. Helper Boundary Execution** | `app/execution/helper/opsforge_helper.py` implements `provision_account` & `remove_account`. `SSHTargetExecutor` stubs raise `NotImplementedError`. | Implement `SSHTargetExecutor.provision_account` and `remove_account` calling helper via `opsforge-svc` sudo boundary. | `tests/execution/test_ssh_provisioning.py` | Helper invoked with positional arguments; zero shell interpolation; manifest updated; sudoers drop-in untouched. | Invariant 6 & 17: `opsforge-svc` has no direct sudo write rights; helper is root-owned 0750 fixed path. |
| **6. Target-Side Verification** | Phase 4 verification pattern exists for rotation. | In `SSHTargetExecutor.provision_account`: open fresh SSH connection to target as `<account>` using *only* new private key; verify shell, password lock, lack of sudo privileges. | `tests/execution/test_ssh_provisioning_verification.py` | Verification confirms target OS user, `/bin/bash` shell, 0600 authorized_keys, no standing sudo. | Invariant 10: Mandatory independent SSH verification before binding activation. |
| **7. Failure Handling & Rollback** | Helper has compensating rollback `userdel -r`. `ExecutionResult` supports `FailureClassification`. | Map helper execution errors and verification failures to safe failure classifications (`EXECUTION_FAILURE`, `AUTHENTICATION_FAILED`, `UNCERTAIN_STATE`). | `tests/target_accounts/test_provisioning_failures.py` | Intermediate failure triggers target rollback; indeterminate state produces `SECURITY_UNCERTAINTY`. | Invariant 11: Fail closed on ambiguity; no silent blind retries. |
| **8. Lazy Provisioning Trigger (Access Request Approval)** | `ApprovalWorkflowService.approve` assigns role upon approval. | Connect approval workflow to `TargetAccountService.provision_target_account` when `requested_resource_id` is present. | `tests/target_accounts/test_provisioning_trigger.py` | Approval of access request triggers provisioning; request creation alone does NOT trigger provisioning. | Invariant 14: Accounts provisioned lazily on first approved request only. |
| **9. Ownership & Authorization** | `app/authorization/service.py` evaluates permissions. | Enforce user ownership on bindings: User A can access User A's binding; User A cannot access User B's binding or resource. | `tests/ownership/test_target_account_ownership.py` | IDOR attempts return 403/Forbidden; cross-tenant bindings rejected. | Invariant 13: Strict multi-tenant cross-object authorization. |
| **10. Real Target Integration** | Disposable SSH container `opsforge-disposable-target` with `opsforge-helper`. | Run live end-to-end provisioning, verification, multi-user isolation, idempotency, and removal against live disposable target. | `tests/execution/test_ssh_provisioning_integration.py` | Live container inspects real `/etc/passwd`, `/var/lib/opsforge/ownership_manifest.json`, and `/var/log/opsforge-helper.log`. | Real target verification on live SSH daemon. |
| **11. Phase Boundary Protection** | No Phase 7+ code in repo. | Strict boundary: NO JIT sudo grants, NO sudoers drop-in creation, NO session proxying. | `tests/test_phase6_boundaries.py` | Codebase inspection verifies zero Phase 7–18 logic. | Strict adherence to Phase 6 scope. |
